# Local HTTP API

Все изменяющие запросы требуют `X-Meeting-Token`, полученный из `GET /api/v1/session`.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/v1/session` | Актуальный локальный token |
| GET | `/api/v1/health` | Проверка сервера |
| GET | `/api/v1/config` | Публичные настройки |
| GET/PUT | `/api/v1/settings` | Описанная схема настроек / проверенное сохранение изменений в `config.toml` |
| POST | `/api/v1/settings` | Проверить несохранённые настройки группы; сейчас поддерживается `group=summary` |
| GET | `/api/v1/audio/devices` | Микрофоны, системные источники и предупреждения |
| GET | `/api/v1/diagnostics` | Диагностика приложения и аудиобэкенда |
| GET | `/api/v1/logs?limit=200` | Последние строки основного лога |
| GET | `/api/v1/search?q=...` | Полнотекстовый и структурированный поиск встреч; возвращает UID совпадений и известные имена спикеров |
| GET/POST | `/api/v1/meetings` | Календарь / ручная встреча |
| GET/PATCH/DELETE | `/api/v1/meetings/{uid}` | Карточка встречи |
| PATCH | `/api/v1/meetings/{uid}/speakers/{speaker_id}` | Переименовать спикера и обновить его метки в транскрипте |
| PATCH | `/api/v1/meetings/{uid}/speakers` | Атомарно сохранить имена, переносы фрагментов и объединения спикеров |
| POST | `/api/v1/recordings` | Создать встречу и запустить нативную запись |
| GET | `/api/v1/recordings` | Текущая активная запись для синхронизации UI и трея |
| POST | `/api/v1/recordings/{uid}/stop` | Остановить и финализировать запись |
| GET | `/api/v1/recordings/{uid}/status` | Активность записи |
| GET | `/api/v1/events` | Поток SSE с изменениями состояния записи |
| GET/DELETE | `/api/v1/meetings/{uid}/artifacts/{artifact_uid}` | Открыть или удалить отдельный файл |
| POST | `/api/v1/meetings/{uid}/artifacts` | Импортировать файл; multipart-поля `file` и `type` |
| POST | `/api/v1/meetings/{uid}/jobs/all/retry` | Повторно запустить обработку подготовленного аудио |
| POST | `/api/v1/meetings/{uid}/jobs/{stage}/retry` | Вручную запустить конкретный этап независимо от его `auto_run` |
| GET | `/api/v1/meetings/{uid}/jobs` | Лёгкий статус этапов и прогресс для UI |
| POST | `/api/v1/meetings/{uid}/jobs/cancel` | Остановить активную обработку, сохранив исходные WAV |
| GET | `/api/v1/models` | Состояние файлов моделей и прогресс загрузки |
| POST | `/api/v1/models/{id}/download` | Скачать/проверить выбранную модель |
| POST | `/api/v1/models/{id}/apply` | Применить установленный комплект модели и обновить `config.toml` |
| POST | `/api/v1/models/{id}/test` | Проверить файлы, SHA-256, ONNX Runtime и открытие ONNX-сессий |

Тело запуска:

```json
{
  "title": "Планирование",
  "input_device": {"id": "device-id", "name": "Microphone"},
  "output_device": {"id": "monitor-id", "name": "System monitor"},
  "participant_count": 8
}
```

Старый endpoint `/chunk` возвращает HTTP 410: браузерная передача PCM удалена. Запись выполняет встроенный нативный backend.

Параметры `transcription.auto_run`, `diarization.auto_run` и `summary.auto_run` определяют только автоматическую цепочку после остановки записи. Отключённый автоматический этап можно запустить вручную. Если выбранный этап завершился ошибкой, следующие автоматические этапы не запускаются.

Поиск принимает точную свободную фразу или условия, разделённые `;`:

```text
Спикеры: Спикер1, Спикер2, !Спикер3; Встреча: Итоги недели; Обсуждение: Мониторинг инфраструктуры; Дата: после 20.09.2026, до 30.09.2026
```

Поддерживаются ключи `Спикеры`, `Встреча`, `Обсуждение`, `Транскрипт`, `Саммари` и `Дата`. Все условия объединяются через «И», отрицательный спикер начинается с `!`, даты `после` и `до` включают указанный день. Текст сравнивается без учёта регистра с нормализацией пробелов, но как единое словосочетание.

Пакетное редактирование спикеров принимает карты `names`, `assignments` (`segment_id → speaker_id`) и `merges` (`from → into`). Микрофонный и системный потоки намеренно нельзя объединять. После успешного сохранения сервер атомарно обновляет текущий слой сегментов, список спикеров и итоговый транскрипт; существующий протокол помечается устаревшим, но не удаляется.

`PATCH /api/v1/meetings/{uid}` принимает `participant_count` от 0 до 65. Это полное число участников, включая владельца микрофона; для диаризации системного звука используется `participant_count - 1`. Значение хранится в метаданных конкретной встречи, `0` возвращает автоматическое определение. Менять его во время активной обработки нельзя.

Для аудио поле `type` принимает `audio_microphone`, `audio_system` или `audio_mixed`. Сервер принимает PCM16 WAV mono/stereo 16 кГц, проверяет RIFF-структуру и помещает поток в канонический каталог `audio/`. Импорты `audio_microphone` и `audio_system` накапливаются: повторная загрузка одного типа не удаляет другой. До появления второго реального потока используется немой WAV той же длительности. `audio_mixed` является отдельным взаимоисключающим режимом. Остальные значения `type` сохраняются как обычные вложения в `imports/`.
