# Известные спикеры и запоминание голосов

Функция связывает голос человека с его именем между встречами. Она состоит из
двух частей:

- **запоминание** — после ручного переименования спикера встреча сохраняет
  несколько чистых образцов его голоса (вектор WeSpeaker + короткий Opus-клип);
- **узнавание** — при следующей встрече кластеры диаризации сравниваются с
  библиотекой. При высокой уверенности имя подставляется автоматически, при
  средней — показывается подсказка, иначе остаётся `SPEAKER_NN`.

Раздел интерфейса называется **«Спикеры»** и показывает только людей с
сохранёнными образцами. Служебные `SPEAKER_NN` в него не попадают.

## Решения

- Библиотека глобальная: один человек может быть спикером многих встреч.
- Человек хранится под уникальным ID. Имя — одно строковое поле; уточнение для
  тёзок пишется в нём же: `Пушкин Александр (писатель)`.
- Запоминаются только спикеры системного потока и mixed-встреч. Микрофонный
  владелец не запоминается.
- Запоминание работает только до архивации аудио. После архивации переименование
  разрешено, но образцы не создаются.
- Автоматически подставленное имя **не** добавляет образцы в профиль. Образцы
  добавляют только ручные действия: ввод имени, принятие подсказки, подтверждение
  авто-имени.
- До 10 образцов на человека, не более 4 с одной встречи.
- Автоподстановка разрешена только для «зрелого» профиля: не менее 8 образцов из
  не менее 2 встреч, высокий score и отрыв от второго кандидата.
- Удаление встречи не удаляет подтверждённые образцы. Удаление профиля убирает
  связь, но оставляет исторические имена в уже сохранённых встречах.
- Профиль без образцов удаляется автоматически.

## Модель данных

`Person`

| Поле | Назначение |
|---|---|
| `id` | UUIDv7, никогда не меняется |
| `name` | отображаемое имя, может содержать уточнение |
| `created_at`, `updated_at` | служебные |
| `needs_qualifier` | у профиля есть тёзка, имя стоит уточнить |

`VoiceSample`

| Поле | Назначение |
|---|---|
| `id` | UUIDv7 |
| `person_id` | владелец образца |
| `meeting_uid`, `speaker_id`, `segment_id` | провенанс для удаления и отладки |
| `source` | `system` или `mixed` |
| `start_ms`, `end_ms` | непрерывный чистый интервал |
| `vector` | нормализованный WeSpeaker-эмбеддинг |
| `dim` | размерность вектора |
| `model_sha256` | отпечаток модели; векторы разных моделей несравнимы |
| `quality` | длительность, RMS, score, признак наложения |
| `clip_path`, `clip_sha256` | короткий Ogg/Opus-клип |
| `created_at` | дата |

Образцы лежат в bbolt, клипы — в `<data_dir>/voices/<person_id>/<sample_id>.opus`.
Клипы создаются с правами владельца.

`Speaker` (карточка спикера встречи) получает поля:

| Поле | Назначение |
|---|---|
| `person_id` | найденный человек |
| `match_score` | уверенность сопоставления |
| `match_candidates` | до 3 подсказок для интерфейса |
| `name_source` | `auto` или `manual` |

Поля `person_id`, `match_score`, `match_candidates`, `name_source` переносятся при
пересборке карточек в `buildSpeakersFromSegments`, иначе сохранение имён их
потеряет.

## Выбор чистых образцов

Диаризация уже считает вероятность каждого локального спикера для каждого кадра.
Для каждого кластера выбираются непрерывные участки, где:

- вероятность этого спикера не ниже 0.60;
- вероятность любого другого спикера ниже 0.45;
- длина участка не меньше 1.5 с; целевая длина 3–10 с.

Участки сохраняются в `diarization_json` вместе с `turns`. Это только тайм-коды,
не биометрия. Если у старой встречи участков нет, они выводятся из `turns`: из
реплики вычитаются пересечения с репликами других спикеров.

Перед сохранением образца дополнительно проверяются RMS, клиппинг и дубликаты:
вектор с косинусом выше 0.98 к уже сохранённому не добавляется.

## Зачисление

Срабатывает после успешного сохранения правок спикеров, только если включена
настройка `diarization.remember_speakers` и аудио встречи ещё не архивировано.

1. Для каждого вручную названного спикера берутся чистые участки, до 4 штук.
2. Из участка вырезается WAV, считаются признаки WeSpeaker и эмбеддинг.
3. Проверяются качество, дубликаты и связность с уже сохранёнными образцами.
4. Профиль определяется по имени и голосу:
   - имя новое — создаётся человек;
   - имя совпадает с существующим и голос похож — образцы добавляются ему;
   - имя совпадает, но голос не похож — создаётся тёзка, профиль помечается
     `needs_qualifier`.
5. Клип и вектор сохраняются, лишние образцы вытесняются по качеству и
   разнообразию.
6. Если чистых участков нет, профиль не создаётся, в ответе возвращается
   предупреждение.

Повторное сохранение идемпотентно: ключ образца — встреча, спикер, интервал и
модель. Ошибка зачисления не отменяет сохранение имён.

## Узнавание

После кластеризации pipeline считает центроиды кластеров и сравнивает их с
образцами людей. Score человека — среднее по трём лучшим образцам.

- **Авто**: score ≥ `autoThreshold`, отрыв от второго ≥ `margin`, профиль зрелый,
  в этой встрече человек ещё не занят другим спикером. Имя подставляется, рядом
  показывается бейдж «авто» и действие «это не он».
- **Подсказка**: score ≥ `suggestThreshold`. Показываются до 3 кандидатов с
  уверенностью и кнопкой прослушивания; нажатие заполняет имя.
- Иначе остаётся `SPEAKER_NN`.

Авто-имена не пополняют профиль. Ручное подтверждение авто-имени или принятие
подсказки — пополняет.

## Этапы обработки

Порядок этапов совпадает с порядком выполнения и с порядком строк во вкладке
«Обработка»:

1. Транскрибация
2. Диаризация
3. Удаление акустического эха (служебный этап)
4. Объединение (служебный этап; в интерфейсе скрыт и сворачивается в строку транскрибации)
5. Распознавание спикеров
6. Создание протокола
7. Запоминание спикеров
8. Сохранение аудио

- **Распознавание спикеров** сравнивает сохранённые центроиды кластеров с
  текущими профилями и обновляет имена, привязки и подсказки. Этап не требует
  аудио. Для встреч, обработанных старой версией, центроиды вычисляются из
  чистых интервалов, если WAV ещё существует. Если аудио уже архивировано и
  центроидов нет, этап пропускается: нужно один раз повторить диаризацию, пока
  WAV доступен.
- **Запоминание спикеров** доступно только при наличии WAV и только для
  вручную названных спикеров. Если аудио архивировано, этап пропускается, а
  кнопка запуска в интерфейсе блокируется.
- Автоматическая цепочка запускает оба этапа: распознавание сразу после
  объединения (до протокола), запоминание после протокола (перед архивацией).
  В автоматической цепочке запоминание обычно пропускается, потому что спикеры
  ещё не названы; его запускают вручную после переименования.
- Каждый этап можно запустить отдельно из вкладки «Обработка». Повторное
  выполнение идемпотентно: уже сохранённые образцы не дублируются.

Центроиды кластеров хранятся в `diarization_json` (schema 3) и удаляются вместе
со встречей. Это биометрические шаблоны, как и сами образцы.

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/v1/people` | профили с образцами и количеством встреч |
| PATCH | `/api/v1/people/{id}` | переименовать человека |
| DELETE | `/api/v1/people/{id}` | удалить человека и все его образцы |
| DELETE | `/api/v1/people` | удалить всех |
| DELETE | `/api/v1/people/{id}/samples/{sample_id}` | удалить один образец |
| GET | `/api/v1/people/{id}/samples/{sample_id}/audio` | прослушать клип |
| GET | `/api/v1/voice/calibration` | рассчитать пороги по подтверждённым и отклонённым подсказкам |

Пакетное сохранение спикеров встречи дополнительно принимает:

- `person_ids` — явная привязка спикера к человеку (нажатие на подсказку);
- `confirm` — подтвердить авто-имя и запомнить голос;
- `reject` — «это не он»: снять привязку и вернуть `SPEAKER_NN`.

Ответ содержит `voice_enrollment` с числом добавленных образцов и
предупреждениями.

## Настройка

`diarization.remember_speakers` (по умолчанию `false`) добавляется в группу
«Диаризация». Описание предупреждает, что голоса — биометрические данные, а
запоминание возможно только до архивации аудио.

Пороги `diarization.voice_auto_threshold` и `diarization.voice_suggest_threshold`
видны в той же группе и применяются вручную. Кнопка «Калибровка» в разделе
«Спикеры» считает значения по подтверждённым, отклонённым и проигнорированным
подсказкам: автоимя подбирается под точность 95%, подсказка — под 90%. Ничего не
применяется автоматически; минимальный набор для расчёта — 10 подтверждений и
5 отклонений.

Каждый образец показывает метку модели: basename файла эмбеддингов и первые
8 символов `model_sha256`. Векторы от разных моделей не сравниваются, но
переиндексация не выполняется автоматически: старые образцы остаются видимыми
и помеченными, пока пользователь не заменит их новыми.

## Крайние случаи

- **Аудио архивировано** — имена сохраняются, образцы нет; интерфейс показывает
  причину и дату, до которой запоминание ещё доступно.
- **`audio_archive_days = 0`** — запоминание не работает; настройка предупреждает.
- **Мало чистого материала** — профиль не создаётся.
- **Два голоса в одном кластере** — образцы плохо связны; профиль не пополняется,
  показывается предупреждение разделить фрагменты.
- **Тёзки** — разные ID; уточнение хранится в имени. При совпадении имени и
  несовпадении голоса создаётся новый профиль.
- **Два спикера одной встречи с одинаковым именем** — при похожем голосе
  связываются с одним человеком (split identity), при разном — создаются тёзки.
- **Повторная диаризация** — номера кластеров могут измениться. Новый кластер
  наследует ручное имя и подтверждённую привязку старого спикера по
  максимальному пересечению по времени, если оно покрывает не менее половины
  нового кластера. Один старый спикер наследуется не более одного раза. Auto-
  имена и auto-привязки пересчитываются заново; при разделении/слиянии кластеров
  имя получает наибольшая часть.
- **Объединение встреч** — `PersonID`, `NameSource`, `MatchScore` и кандидаты
  переносятся. Если один и тот же объединённый спикер пришёл из двух кластеров с
  разными людьми, привязка очищается, чтобы не переименовать одного человека
  другим; подсказки остаются. Клипы уже скопированы в профиль, провенанс может
  ссылаться на старую встречу.
- **Удаление профиля** — имена в прошлых встречах остаются, связь снимается.

## Приватность

- Глобальный выключатель; при выключении новые образцы не создаются и матчинг не
  выполняется, существующие профили остаются.
- Удаление образца, человека и всех профилей.
- Клипы и векторы не покидают компьютер, сервер слушает только loopback.
- bbolt не шифруется: защита данных на диске — ответственность ОС. Это отмечено
  в описании настройки.

## Тесты

- выбор чистых участков и отказ при наложении;
- идемпотентность зачисления;
- вытеснение образцов и удаление профиля без образцов;
- сохранение полей привязки при пересборке карточек;
- матчинг: авто, подсказка, отказ при малом отрыве, конфликт двух кластеров;
- архивированное аудио и отсутствие чистых участков;
- API-удаление и выдача клипов.
