# Проверка

Один документ на все виды проверки: автотесты, ручная приёмка на macOS и чек-лист
для Windows и Linux. Отмечайте пункты прямо в файле.

## Автоматически

```bash
go test ./...
go vet ./...
node --check internal/server/web/app.js
```

`TestRecordingCalendarEndToEnd` использует встроенный синтетический PCM-backend и
проверяет полный цикл: API запуска → два WAV → остановка → смешивание → артефакты →
запись календаря. В тестах нет зависимости от FFmpeg и реального аудиоустройства.

### Что покрыто тестами

**Запись и аудио**

- полный цикл записи на синтетическом backend и календарная запись встречи;
- пустой системный WAV не считается ошибкой встречи;
- восстановление системного потока после смены устройства и запись события
  `restored`/`lost` (`TestSystemAudioRecoveryIsRecorded`);
- текст предупреждения о звуке на двух языках (`TestAudioWarningText`);
- импорт системного PCM16 WAV и повторная обработка без второго mixed-прохода;
- последовательный импорт microphone/system без взаимного удаления файлов;
- создание валидного Ogg/Opus встроенным Go-кодировщиком;
- восстановление канонической WAV-пары из единственного Ogg/Opus.

**Транскрибация и диаризация**

- точная кластеризация WeSpeaker-эмбеддингов с cannot-link для дорожек одного окна;
- разбиение VAD-региона без потери последнего фрагмента;
- назначение спикера по максимальному пересечению интервалов;
- выбор самых длинных реальных интервалов диаризации для образцов голоса;
- удаление совпадающей эхокопии и сохранение отличающейся одновременной речи;
- обнаружение повторяющейся галлюцинации и разметка владельца микрофона;
- полный mock-конвейер с двумя потоками и диаризацией;
- сохранение транскрипта и job `failed`, если диаризатор недоступен;
- миграция старого `whisper.cpp` engine на нативный runtime;
- извлечение из официального whisper.cpp runtime только библиотек без CLI-файлов.

**Спикеры, протокол и настройки**

- пакетное переименование, перенос фрагмента и объединение Speaker с перестройкой
  транскрипта;
- создание спикера вручную, перенос в него фрагментов одним запросом, сохранение
  пустого спикера и отказы на дубликат id, чужой поток и превышение лимита;
- переименование метки спикера без замены совпадений внутри произнесённого текста;
- сохранение последнего успешного протокола при неудачной повторной саммаризации;
- проверка подключения к OpenAI-совместимой модели с несохранёнными значениями формы;
- горячее применение настроек со списком параметров, требующих перезапуска;
- схема саммаризации: разделы «Сетевой эндпоинт» и «Локальная модель» показываются
  только для своего движка, все поля остаются в схеме;
- `.hidden` побеждает `display: !important` у строк настроек.

**Модели и рантаймы**

- карточки моделей, рекомендуемый набор и переключение движка вместе с моделью;
- выбор модели эмбеддингов диаризации (ResNet34 / CAM++) и признак «применена»;
- карточки локальной саммаризации и Vulkan-рантайма;
- путь рантайма llama.cpp совпадает с тем, что устанавливает карточка;
- распаковка архивов рантаймов с симлинками (tar и zip);
- докачка `.download.part` после HTTP 416 без повторной передачи файла.

**Прочее**

- идемпотентное восстановление скопированной встречи и её артефактов при старте;
- удаление файла и записи из bbolt;
- UTF-8 Content-Type для Markdown-транскриптов;
- лёгкий endpoint прогресса и сохранение процентов этапов;
- локализация интерфейса: все ключи из `index.html` и `app.js` есть в обоих языках.

### Проверки, требующие внешних файлов


## Ручная приёмка на macOS

### Установка из .dmg

- [ ] Собрать образ (`./scripts/make-app.sh <версия> dist`) или взять из релиза.
- [ ] Открыть `.dmg`, перетащить **LocalMeetAssist** в «Программы», запустить
      оттуда — приложение должно стартовать из Finder (рабочий каталог `/`).
- [ ] macOS спрашивает **только микрофон**; запроса на запись экрана нет.
- [ ] Настройки, база и модели появляются в `~/Library/Application Support/LocalMeetAssist/`.
- [ ] Иконка есть в меню-баре и в Dock; в «Мониторе системы» у процесса есть иконка.
- [ ] `otool -l LocalMeetAssist.app/Contents/MacOS/localmeetassist | grep -A3 LC_BUILD_VERSION`
      показывает `minos 14.2`; `lipo -info` — `x86_64 arm64`.
- [ ] `codesign -dv /Applications/LocalMeetAssist.app` показывает подпись,
      `spctl -a -t exec` ожидаемо ругается только из-за отсутствия нотаризации.

### Запись и обработка

- [ ] «Настройки» → «Диаризация»: модели сегментации и голосовых признаков — выпадающие списки; незагруженные модели видны серым и не выбираются; произвольный путь из конфига не теряется.
- [ ] «Повторить этап»: после нажатия строка этапа остаётся на своём месте (transcribing → diarizing → summarizing → encoding), а не уезжает вниз.
- [ ] «Спикеры»: кнопка «Новый спикер» стоит отдельно от «Переместить выбранные» и не нажимается случайно.
- [ ] Определение конференции: начать запись по активности, завершить звонок — через `conference_detection.stop_after_idle_seconds` запись останавливается сама; при 0 не останавливается.
- [ ] Плагин: ручной старт из попапа, затем переход на другой адрес или закрытие вкладки — запись останавливается через задержку плагина; перезагрузка той же страницы запись не обрывает.
- [ ] Встреча, сжатая в Opus и восстановленная из общего потока: в «Файлах» только общий поток, в карточке предупреждение, а фрагменты микрофона и системы играются из него же по тем же таймкодам.

0. Разрешение на микрофон: при первом запуске .app появляется системный запрос.
   Если запретить доступ, запись должна завершиться понятной ошибкой, а не пустой
   дорожкой. При запуске из терминала в логе есть строка `microphone: permission
   is not confirmed`.
1. «Диагностика»: системные имена обоих устройств на месте, предупреждений нет.
2. Записать 1–2 минуты: свой голос в микрофон и два-три удалённых голоса через
   системный звук; проверить отдельно `microphone.wav` и `system.wav`.
3. Дождаться обработки: jobs `transcribing`, `diarizing`, `deduplicating`,
   `merging` завершились, в карточке появился протокол.
4. Сравнить JSON исходных транскриптов с итоговым Markdown: удалённая эхокопия
   отсутствует только в итоговом файле.
5. «Спикеры»: переименовать, выделить диапазон Shift-кликом, перенести его кнопкой
   «Переместить выбранные», объединить две карточки перетаскиванием и сохранить всё
   одной кнопкой. Отдельно проверить «Новый спикер» на встрече, где система нашла
   одного участника вместо двух.
6. Временно указать неверный путь к модели диаризации: встреча получает статус
   «С предупреждением», транскрипт сохраняется со `SPEAKER_00`.
7. Локальные протоколы: скачать Qwen3.5-4B, применить, собрать протокол; проверить,
   что текст не уходит в сеть (нет запросов к эндпоинту).
8. Отключить дополнительный экран во время записи: системный звук не пропадает, а
   запись продолжается.
9. Переключить устройство вывода во время записи: в логе
   `native recording system audio restored`, в карточке предупреждение, во второй
   половине записи есть звук.
10. Перезапустить приложение: встреча и её артефакты на месте.

## Windows и Linux

Обе ОС используют общий C-слой `internal/nativeaudio/nativeaudio.c`, поэтому проверки
почти одинаковые; отличия отмечены. Нужны MinGW-w64 с GCC в `PATH` (Windows) или
`gcc` с заголовками PulseAudio/ALSA (Linux). Лог: `data/logs/localmeetassist.log`.

### 0. Установка пакетом

- [ ] `sudo apt install ./localmeetassist_<версия>_amd64.deb` (или
      `sudo dnf install ./localmeetassist-<версия>-1.x86_64.rpm`) проходит без
      ошибок зависимостей: `libayatana-appindicator3` и X11 подтягиваются сами.
- [ ] После установки `localmeetassist` есть в `PATH`, а в меню появился пункт
      с иконкой; запуск из меню открывает трей и браузер.
- [ ] Настройки, база и модели появляются в `~/.config/LocalMeetAssist/`.
- [ ] `sudo apt remove localmeetassist` удаляет бинарник, иконку и `.desktop`,
      но не трогает данные пользователя.
- [ ] Архив `.tar.gz` на системе без этих библиотек запускается только после их
      установки — проверить сообщение загрузчика, чтобы знать, что писать в
      поддержке.

### 0a. Windows: двойной клик

- [ ] `localmeetassist.exe` запускается двойным кликом **без консольного окна**.
- [ ] Приложение появляется в трее, интерфейс открывается в браузере.
- [ ] Проверить видимость ранней ошибки: указать в ярлыке параметр
      `-config` на недоступный путь (например, на чужую папку без прав) —
      должен появиться MessageBox с текстом ошибки, а рядом с конфигом
      создаётся `startup-error.log`.
- [ ] SmartScreen на неподписанной сборке: «Подробнее» → «Выполнить в любом
      случае», приложение запускается.

### 1. Базовый захват системного звука

- [ ] Начать запись, включить любой звук (ролик, музыка, звонок).
- [ ] В логе нет `cannot open system audio` и `cannot start system audio`.
- [ ] После остановки в `audio/system.wav` есть звук, `microphone.wav` не пустой.
- [ ] Встреча сохранилась и ушла в обработку (`pipeline start` в логе).

Windows: WASAPI loopback захватывает системный звук и звук приложений.
Linux: нужен monitor-источник PulseAudio/PipeWire; проверьте выбранный источник в
строке `native recording start ... system="..."`.

### 2. Смена устройства вывода во время встречи

- [ ] Начать запись, включить звук.
- [ ] Переключить вывод на наушники/Bluetooth или отключить монитор со колонками,
      если он был устройством по умолчанию.
- [ ] В логе `native recording system audio restored`.
- [ ] `system.wav` продолжает расти, после переключения в записи есть звук.
- [ ] В карточке предупреждение «Системный звук пересоздан в HH:MM…».
- [ ] Встреча сохранилась и обработалась, статус не `failed`.

### 3. Отрицательный сценарий: устройство не вернулось

- [ ] Убрать все устройства вывода во время записи.
- [ ] В логе `native recording system audio lost`, повторных попыток нет.
- [ ] В карточке «Системный звук потерян в HH:MM…».
- [ ] Запись останавливается, встреча **сохраняется** и обрабатывается, микрофон цел.

### 4. Долгая запись

- [ ] Записать не менее часа.
- [ ] Оба WAV валидны, длительность совпадает с длительностью встречи.
- [ ] При штатной остановке нет `recording stop warning`.

### 5. Микрофон (известный пробел)

- [ ] Выдернуть USB-микрофон во время записи. Восстановление микрофонной дорожки
      **не реализовано** (в отличие от системного звука).
- [ ] Зафиксировать фактическое поведение: падает запись целиком или сохраняется с
      предупреждением. Если падает — завести задачу на такое же восстановление.

### 6. Диаризация с альтернативной моделью эмбеддингов

- [ ] «Модели» → «Спикеры»: карточка **WeSpeaker CAM++ VoxCeleb** видна.
- [ ] «Скачать» (~28 МБ), затем «Проверить» — интерфейс `feats`/`embs` проходит.
- [ ] «Применить»: `diarization.embedding_model` указывает на CAM++.
- [ ] Диаризация на встрече с двумя-тремя участниками: `diarization completed ... speakers=N`,
      число спикеров правдоподобное.
- [ ] Сравнить с ResNet34 на той же встрече и записать оба результата.

### 7. Локальная саммаризация и рантаймы

- [ ] «Модели» → «Runtime»: скачать **llama.cpp native runtime**.
      Linux: проверить, что `runtime/llama.cpp/<os>-<arch>/libllama.so.0` существует
      (ссылка или копия) и «Проверить» проходит.
      Windows: в каталоге появились `llama.dll`, `ggml.dll`, `ggml-base.dll`,
      `ggml-cpu.dll`, `libomp.dll`, `llama-common.dll`.
- [ ] Скачать Qwen3.5-4B, «Применить»: движок саммаризации переключился на локальный.
- [ ] «Проверить» в настройках саммаризации: модель загружается и генерирует ответ.
- [ ] Протокол на реальной встрече: русский язык, все разделы на месте.
- [ ] (Windows/Linux) карточка **llama.cpp Vulkan runtime**: скачать, применить,
      повторить протокол и **замерить скорость** относительно обычной сборки. При
      сбое зафиксировать ошибку и вернуть обычный рантайм.

### 8. Интерфейс

- [ ] «Модели»: четыре вкладки — Runtime / Транскрибация / Спикеры / Протоколы —
      в одну строку.
- [ ] «Настройки» → «Саммаризация»: при сетевом движке виден только раздел
      «Сетевой эндпоинт», при локальном — только «Локальная модель»; общие параметры
      видны всегда.
- [ ] «Спикеры»: Shift-клик выделяет диапазон включая обе границы, «Новый спикер»
      создаёт карточку и переносит в неё выделенное, после сохранения список не
      теряет нового спикера.
- [ ] Предупреждение о системном звуке не висит на встречах, где проблем со звуком
      не было.
- [ ] В логе есть строка `system audio tap: ... buffer N of M`; при гарнитуре с
      микрофоном M=2 и N=1, при обычных колонках M=1 и N=0. Значение N=0 при M=2
      означало бы, что в системную дорожку попал микрофон.
- [ ] Запись через Bluetooth-гарнитуру: в логе `capturing 44100 Hz into 16000 Hz
      (step 2.7563)`, длительность системной дорожки совпадает со встречей, голос
      не ускорен. Это отдельная проверка: тап заявляет 48 кГц, а данные приходят в
      частоте устройства 44.1 кГц.
- [ ] Переключение вывода во время записи (гарнитура ↔ колонки): запись не
      прерывается, в логе появляется новая строка `capturing ... into 16000 Hz`,
      длительность системной дорожки совпадает с длительностью встречи, голос не
      ускорен. Пауза на пересоздание агрегата дописывается тишиной.
- [ ] Переключение микрофона во время записи (гарнитура ↔ встроенный): в логе
      `native recording microphone restored`, микрофонная дорожка продолжается без
      сдвига относительно встречи. Значение по умолчанию следует за системным
      входом, явно выбранное устройство остаётся, а при его исчезновении берётся
      системное.

## Известные пробелы

1. **Микрофон** при пропаже устройства не восстанавливается — см. пункт 5 для
   Windows/Linux. На macOS пересоздаётся только системный поток.
2. **Качество диаризации** зависит от акустики и канала: WASAPI/PulseAudio могут
   отдавать другой формат (моно/стерео, частота), стоит сравнить число спикеров с
   macOS на одной и той же записи.
3. **Vulkan** проверяется только на машине с подходящей видеокартой.
4. **Верстка** проверяется глазами: автотесты ловят ключи, классы и схему, но не
   расположение элементов.
5. **Пакеты Linux** собираются только в CI: `dpkg-deb` и `rpmbuild` есть на
   ubuntu-раннерах, но не в песочнице разработки на macOS. Локальная проверка —
   только структура (`scripts/make-linux-package.sh` со заглушками в `PATH`).
6. **Нотаризация не настроена.** `.app` подписан ad-hoc, поэтому скачанный из
   интернета образ требует одного подтверждения (ПКМ → «Открыть» или снятие
   карантина). Для установки двойным кликом нужен Developer ID и секреты
   `MACOS_SIGN_IDENTITY`, `MACOS_NOTARY_APPLE_ID`, `MACOS_NOTARY_TEAM_ID`,
   `MACOS_NOTARY_PASSWORD` — скрипт уже умеет подписывать и нотаризовать при их
   наличии.
7. **Создание .dmg** нельзя проверить в песочнице разработки: `hdiutil` там
   недоступен, поэтому образ собирается только в CI. Для локальной проверки
   бандла используйте `NO_DMG=1 ./scripts/make-app.sh <версия> dist`.
