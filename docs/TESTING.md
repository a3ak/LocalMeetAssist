# Проверка

## Автоматически

```bash
go test ./...
go vet ./...
node --check internal/server/web/app.js
```

`TestRecordingCalendarEndToEnd` использует встроенный синтетический PCM-backend и проверяет полный цикл: API запуска → два WAV → остановка → смешивание → артефакты → запись календаря. В тестах нет зависимости от FFmpeg и реального аудиоустройства.

Тесты pipeline дополнительно проверяют:

- точную кластеризацию WeSpeaker embeddings с cannot-link для дорожек одного окна;
- разбиение VAD-региона без потери последнего фрагмента;
- назначение спикера по максимальному пересечению интервалов;
- удаление совпадающей эхокопии и сохранение отличающейся одновременной речи;
- полный mock-конвейер с двумя потоками и диаризацией;
- сохранение транскрипта и job со статусом `failed`, если диаризатор недоступен.
- обнаружение повторяющейся галлюцинации и разметку владельца микрофона в mixed-транскрипте;
- удаление отдельного файла и соответствующей записи из bbolt;
- импорт системного PCM16 WAV в канонический поток и повторную обработку без второго mixed-прохода;
- последовательный импорт microphone/system без взаимного удаления файлов и артефактов;
- подавление массового повтора одной гипотезы и непрерывного вырожденного хвоста;
- горячее применение рабочих настроек с явным списком параметров, требующих перезапуска;
- UTF-8 Content-Type для Markdown-транскриптов;
- выбор самых длинных реальных интервалов диаризации для голосовых образцов спикеров;
- переименование метки спикера в записи встречи и Markdown-артефакте без замены совпадений внутри произнесённого текста;
- лёгкий endpoint прогресса, сохранение процентов этапов и системного промта саммаризации;
- создание валидного Ogg/Opus встроенным Go-кодировщиком.
- восстановление полностью скачанного `.download.part` после HTTP 416 без повторной передачи файла;
- сохранение последнего успешного протокола при неудачной повторной саммаризации;
- пакетное переименование, перенос фрагмента и объединение Speaker с перестройкой транскрипта;
- проверку подключения к OpenAI-совместимой модели с несохранёнными значениями формы.
- миграцию старого `whisper.cpp` engine на нативный runtime и применение каждой Whisper-модели вместе с правильным движком;
- извлечение из официального whisper.cpp runtime только библиотек без CLI-файлов;
- удаление обрезанной или разбитой на соседние сегменты эхокопии.
- идемпотентное восстановление скопированной встречи, её артефактов, транскрипта, саммари и карточек спикеров при старте;
- восстановление канонической WAV-пары из единственного Ogg/Opus без удаления сжатого исходника.

## На реальном оборудовании

Автотест не заменяет проверку драйверов на целевой ОС:

1. открыть «Диагностика» и проверить системные имена обоих устройств;
2. записать не менее 30 секунд голоса и воспроизводимого звука;
3. проверить отдельно `microphone.wav` и `system.wav`;
4. проверить смешанный WAV во встроенном плеере;
5. перезапустить приложение и убедиться, что событие осталось в календаре;
6. повторить с явно выбранными устройствами и с устройствами из `config.toml`;
7. отключить/занять устройство и проверить, что ошибка видна в календаре и логах.

## Приёмка распознавания на macOS

1. В окне «Модели» убедиться, что ONNX Runtime и четыре комплекта файлов имеют статус «Установлена».
2. Записать 1–2 минуты: локальный голос в микрофон и не менее двух удалённых голосов через системный звук.
3. Повторить запись через колонки, чтобы удалённый голос попал также в микрофон.
4. Дождаться автоматического обновления карточки и проверить jobs `transcribing`, `diarizing`, `deduplicating`, `merging`.
5. Сравнить JSON двух исходных транскриптов с итоговым Markdown: удалённая эхокопия должна отсутствовать только в итоговом файле.
6. Проверить `SPEAKER_00` и `SPEAKER_01`, изменить несколько имён, перенести фрагмент Drag&Drop, объединить две карточки и сохранить всё одной кнопкой.
7. Временно указать неверный путь к модели диаризации: встреча должна получить статус «С предупреждением», но транскрипт должен сохраниться с `SPEAKER_00`.
