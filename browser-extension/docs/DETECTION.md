# Обнаружение и управление вкладками — 0.1.0

Нормативные правила: [BROWSER_PLUGIN.md](BROWSER_PLUGIN.md), разделы 7–9.

Каждая вкладка учитывается по `tab.id`; одинаковые URL остаются разными строками списка.
При первом запуске все существующие страницы старые. История `storage.session` переживает выгрузку background,
но не перезапуск браузера. F5 и повторное событие того же URL не обновляют возраст.
Новая вкладка, SPA-навигация и новый подходящий URL в существующей вкладке — новые варианты.

Новый запуск допускается после N=3 с (0–30), если странице не более O=180 с (30–300).
Уже допущенный управляющий источник остаётся активным после O.
Отказ исключает все уже открытые варианты; новый вариант того же GLOB снова допускается через N, без cooldown.
Любое завершение записи помечает текущие подходящие страницы устаревшими.

Источник URL/GLOB сохраняется. После старта другие уже открытые варианты не становятся запасными управляющими.
Закрытие controller запускает локальную настройку `stopDelaySeconds` (0–300 с, по умолчанию 5). Только новая страница того же GLOB
до срока продолжает запись: без начальной задержки N и без пересоздания встречи. Повторный скан срок не обновляет.
Новый URL в том же controller тоже является новым вариантом. Старый дубликат/F5 не продолжает запись.
Если срок истёк, расширение отправляет `stop_manual`; сервер не останавливает запись по пустому набору.

Кнопка ожидания включает 60 с, повторный клик обновляет срок. Новый подходящий вариант автоматически получает
управление; можно явно выбрать любую активную вкладку. После явного выбора навигация разрешена, закрытие вкладки
включает обычную задержку. Серверу всё время передаётся первоначальный URL встречи.
Без успешного переключения за 60 с: открытый controller остаётся; закрытый включает обычную задержку.

Таймеры исполняются в background и подстрахованы alarm. Во время сна ОС сроки не гарантируются до миллисекунды;
при пробуждении проверяются абсолютные дедлайны. Краткая потеря канала сама по себе не завершает запись. Если браузерный владелец не восстановился
за серверное окно, сервер завершает браузерную запись; запись приложения остаётся.

После полного перезапуска история страниц очищается, но минимальный контекст браузерной записи
проверяется по client_id, recording_revision, owner и state. При той же записи плагин восстановит
исходный URL/GLOB и включит ожидание 60 секунд без старого controller. Отправка исходного URL
поддерживает существующую запись; все восстановленные страницы остаются старыми для нового запуска.
Новая страница того же GLOB или явный выбор любой активной вкладки передают управление.
Без выбора — stop через 60 с плюс задержка. Повторный запуск worker и reconnect не обновляют сроки.
Потеря владения или смена записи отменяют автоматическую остановку, чтобы не завершить чужую встречу.

Задержка берётся из настроек расширения, config её не задаёт. При наблюдаемом завершении
сначала отправляется обычный пустой tabs; все найденные к этому моменту варианты становятся
устаревшими. Только последующее новое посещение может вызвать новый вопрос или запуск.
