# Проверка версии 0.1.0

```sh
npm run package
```

Автоматические проверки: JS синтаксис, ресурсы/manifest/CSP, иконки PNG, API wrapper,
интерфейс на DOM-стабах, логика age/delay/controller/hold, устойчивость команд и реальный WebSocket с mock.
Настоящий LocalMeetAssist и браузерный аудиодвижок в этот проект не входят.

## Стенд без аудиозаписи

```sh
npm run mock
```

Порт по умолчанию **52469**, фиктивный токен **lma_pl_DEMO_ONLY**. Настройте расширение этими значениями,
откройте новую `http://127.0.0.1:52469/demo`, подождите 3 с и подтвердите вопрос.
Кнопки кружка/квадрата проверяют глобальный start/stop. Закрытие controller через 5 с приводит к stop плагина.
Mock не записывает звук. Другой порт/режим: переменные `LMA_MOCK_PORT`, `LMA_MOCK_MODE` (notify/auto).
После теста верните реальный порт/токен. Mock-код — иллюстрация протокола, не production сервер приложения.

## Ручная приёмка в Chrome/Edge/Firefox

- Загрузить dist-сборку; проверить светлую/тёмную тему, LM-иконку, жёлтый ?, нативное уведомление.
- Первые существующие страницы старые; новая допускается через N; F5 не меняет вариант.
- Проверить N=0/3/30, O=30/180/300 и недопустимые значения.
- Decline для нескольких открытых страниц: всё отклонено, новая того же GLOB снова задаёт вопрос.
- Старт/завершение в приложении отражается в плагине; Stop плагина завершает запись приложения/другого профиля.
- Кнопка Start при активной записи не создаёт вторую встречу.
- Старые дубликаты не спасают закрытый controller; новая вкладка/новый URL того же GLOB до срока продолжают запись.
- Сообщение продолжения совпадает с текстом спецификации; источник URL не меняется.
- Другой GLOB не продолжает исходную запись. Через обычную задержку уходит один stop.
- Hold на 60 с; повторное нажатие обновляет отсчёт; выбор любой активной вкладки передаёт управление.
- Закрыть исходную после выбора другой: запись продолжается. Закрыть выбранную: начинается задержка.
- Время hold истекло: открытая управляющая остаётся; закрытая запускает обычную задержку.
- Меню URL: группировка GLOB, дубликаты отдельными строками, отметки источника/controller, закрытие одной/всех.
- Кнопка «Закрыть все» не закрывает посторонние вкладки; закрытие controller не обходит обычную задержку.
- Завершение записи делает текущие страницы старыми; только новый URL/вкладка возобновляют обнаружение.
- Выгрузить worker/event page: source, controller и остатки сроков восстановлены.
- Потерять ack/reconnect: тот же command_id, нет повторного действия, особенно stop следующей встречи.
- Закрыть браузер/оборвать канал: запись по GLOB сохраняется до серверного окна, затем завершается. Ручная запись приложения/Start продолжается. Offline отключает команды.
- Heartbeat отражает записи без вкладок; перезапуск приложения сохраняет revision и UUID-кэш, завершает прежнюю активную запись с увеличением revision.
- Отозвать токен: forbidden без циклических повторов; изменить порт/токен для возобновления.

Результаты выполненных автоматических проверок: [VALIDATION.md](VALIDATION.md).
Реальные OS-уведомления, браузерный lifecycle и аудио проверяются этим чеклистом отдельно.

## Приёмка восстановления 0.1.0

- Постоянно установленные Chrome и Firefox: начать по GLOB, полностью перезапустить браузер
  до серверного окна; та же запись, автоматическое ожидание 60 секунд и отсутствие controller.
- Старые восстановленные страницы/F5 не подхватывают управление. Новая страница того же GLOB
  подхватывает сразу; явно можно выбрать любую старую/неподходящую активную вкладку.
- Без выбора: stop через 60 секунд плюс задержка; повторное нажатие обновляет отсчёт.
- Выгрузка worker, reconnect и закрытый popup не сбрасывают абсолютные сроки.
- Завершить запись в приложении во время ожидания: idle, owner false, нет prompt, удалён контекст.
- Перезапустить приложение во время записи: false и увеличенный revision; старую запись не восстанавливать.
- Пропущенный конец/новый старт, потеря владельца: старый автоматический Stop следующую запись не завершает.
- Порт не закреплён / закреплён новый порт: видны соответствующие предупреждения.
- unsupported_protocol и 1002 прекращают повторы, сохранение прежних настроек блокировку не обходит.

Mock использует память для журнала активности/revision и кэша команд, с инъекцией часов в тестах.
Проверки журнала моделируют границу процессов; они не доказывают атомарность постоянного хранилища
настоящего Go-сервера. Эту гарантию и сохранение UUID-кэша требуется проверить отдельно на сервере.

## Приёмка опубликованного контракта 1.0

- Проверить hello/config protocol_version=1 и config без stop_delay_seconds.
- Проверить локальную задержку 0/5/300, отклонение -1/301/дробных значений, миграцию старых настроек в 5.
- Изменить delay при идущем отсчёте: текущий срок сохраняется, следующий использует новое значение; WebSocket остаётся прежним.
- При ручной записи приложения/Start закрыть все страницы: локальный delay не завершает запись.
- При внешнем завершении увидеть обычный tabs.urls=[] без command_id; текущие страницы не запускают новую запись.
- Настроить на сервере N=2/4/10, poll=10/20/25: после закрытия grace=N*poll, при молчании суммарно (2+N)*poll.
- При N=2, poll=10 восстановить доступный транспорт до 40 с после последнего сообщения; watchdog срабатывает на 35 с, быстрые попытки не ждут длинный backoff.
- Полный browser restart: той же записи даётся 60 с плюс локальный delay; новый worker/reconnect не сбрасывает срок.
- Обновить с 1.3.0 после отказа чернового протокола: новый hello допускается без смены токена. Отказ версии 1 или forbidden продолжает блокировать повторы.
