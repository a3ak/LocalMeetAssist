# Протокол и совместимость — спецификация 1.0, protocol_version 1

Нормативный документ: [BROWSER_PLUGIN.md](BROWSER_PLUGIN.md). Версия расширений — 0.1.0.
WebSocket: `ws://127.0.0.1:<port>/api/v1/ws`. Первое сообщение — hello с токеном,
постоянным client_id и `protocol_version: 1`. Config также объявляет версию 1 и обе capability:
`manual_tabs`, `recording_state`. До config и state управляющий набор не отправляется.
Несовместимый config отключает действия; unsupported_protocol/1002 останавливает повторы.
При обновлении сбрасывается отказ старого чернового протокола, отказ версии 1 сохраняется.

## Настройки

Сервер задаёт enabled, patterns, mode, title_template и poll_interval_seconds (10–25 с),
listen_port/effective_port. `stop_delay_seconds` не читается; его отсутствие не ошибка.
Локальная настройка stopDelaySeconds — целое число 0–300 с, исходно 5. Она применяется
только к потере controller собственной браузерной записи и к окончанию её 60-секундного ожидания.
Ручная запись приложения/record_manual и запись другого профиля не получают автоматический Stop.
Изменение временных настроек не переподключает канал и не обновляет начатый дедлайн.

## Запись и команды

Глобальные recording_active/recording_revision приходят в state и ask. Состояния сессии:
idle, recording, awaiting_confirmation. Offline означает неизвестное состояние записи.
Внешнее завершение освобождает owner/prompt, даёт idle/false и увеличенный revision.
Плагин удаляет локальный контекст, помечает текущие варианты устаревшими и отправляет обычный
пустой tabs без command_id. Непустой набор сохранён сервером до этого пустого сообщения.
Новый запуск допускается только для последующего нового варианта.

Ручные действия используют только точные URL https://localmeetassist.local/record_manual и
https://localmeetassist.local/stop_manual в tabs с command_id и seq на соединение.
Обычный ack не завершает команду: нужен её ID и applied/noop/rejected. UUID повторяется после
reconnect, маркер отправляется один раз на соединение. Сервер дедуплицирует UUID.
Автоматический Stop старой записи отменяется при смене revision или владельца.

## Потеря транспорта

Серверная настройка N=stop_after_missed_polls принимает 2–10, исходно 4.
После обнаруженного закрытия соединения RECONNECT_GRACE=N*poll. При молчании открытого канала
сервер сначала обнаруживает отсутствие сообщений после 2*poll; суммарный срок — (2+N)*poll.
При N=4 и poll=20 это 80 с после закрытия или 120 с с последнего принятого сообщения при молчании.
Пустой набор не запускает это окно и не останавливает запись. Потеря браузерного владельца
может завершить только его браузерную запись; ручные записи продолжаются.

N не передаётся плагину в config, поэтому транспорт рассчитывается на минимальное N=2.
Watchdog остаётся 3*poll+5 с. При минимальном poll=10 это 35 с против серверного срока 40 с.
В пределах оставшегося окна повторные попытки идут через 1 с, сроки подключения/handshake
ограничены остатком окна с резервом; согласованный poll сохраняется между попытками.
После обычного закрытия используется минимум 2*poll. За пределами окна применяется backoff
до 30 с. Это обеспечивает раннюю попытку восстановления при доступном локальном сервере;
сон ОС или недоступность приложения могут исчерпать окно. Watchdog/ack timeout не посылают Stop.

## Полный перезапуск

Минимальный storage.local контекст содержит schema_version, client_id, source_url, source_glob,
recording_revision. При той же записи с state=recording, owner=true, active=true восстанавливается
источник и начинается ожидание 60 с без controller. Старые восстановленные страницы устаревшие;
отправляемый source_url поддерживает существующую запись, а не допускает новый запуск.
Новая страница того же GLOB или явный выбор любой активной вкладки передают управление.
Без выбора — Stop после 60 с плюс локальная задержка. Worker restart/reconnect не обновляют срок.
Другой revision, потеря owner, завершение, отключение интеграции, смена порта/токена или очистка
настроек удаляют контекст. Серверный процесс не восстанавливает аудиозапись после перезапуска.
